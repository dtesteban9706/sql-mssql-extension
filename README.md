# custom:sql.mssql.wait-stats

Dynatrace Extensions 2.0 extension for deep SQL Server wait stats observability. Collects Query Store wait statistics, instance-level DMV wait totals, and active session wait details — ingested as logs for flexible DQL querying and as metrics for alerting.

## Feature Sets

| Feature Set | Group | Interval | Ingest | What it captures |
|---|---|---|---|---|
| Queries | `query_wait_stats` | 60 min | log | Query Store wait stats per query (wait category, total/avg/max ms, SQL text) |
| DMV Wait Stats | `dmv_instance_wait_stats` | 5 min | log | Instance-level wait category totals from `sys.dm_os_wait_stats` |
| DMV Wait Stats | `dmv_active_wait_stats` | 1 min | log | Active session waits, blocking chains, elapsed/CPU time, logical reads |
| DMV Wait Stats | `metric_active_sessions` | 1 min | metrics | Blocking session count, max active wait ms, max elapsed ms |
| DMV Wait Stats | `metric_instance_waits` | 5 min | metrics | Cumulative lock / I/O / CPU wait totals |

## Prerequisites

- Dynatrace tenant with **Extensions 2.0** support (v1.279+)
- **ActiveGate** (v1.239+) reachable from your SQL Server, with the Database Observability module enabled
- SQL Server login with at minimum `VIEW SERVER STATE` permission
- Python 3.8+ on the machine used for signing and uploading
- [dt-cli](https://github.com/dynatrace-oss/dt-cli):
  ```bash
  pip install dt-cli
  ```
- A Dynatrace API token with scopes: `extensions.read`, `extensions.write`

## Deployment

### 1. Generate a signing certificate (one-time per tenant)

If you don't already have a developer certificate for this tenant, generate one now. Keep these files safe — you'll reuse them for every future upload.

```bash
# Generate CA key + self-signed certificate
dt extension genca --ca-crt ca.pem --ca-key ca.key

# Generate developer certificate signed by that CA
dt extension generate-developer-pem \
  --ca-crt ca.pem \
  --ca-key ca.key \
  -o developer.pem
```

Then upload `ca.pem` to your Dynatrace tenant:

> **Settings → Extensions → Extension execution controller → Add new certificate**

Paste the contents of `ca.pem` and save.

---

### 2. Build the extension

From the root of this repository:

```bash
dt extension assemble --src src --output build/extension.zip
```

---

### 3. Sign the bundle

```bash
dt extension sign \
  --src build/extension.zip \
  --key developer.pem \
  --output build/bundle.zip
```

---

### 4. Upload to your tenant

```bash
dt extension upload build/bundle.zip \
  --tenant-url https://<your-tenant>.dynatracelabs.com \
  --api-token <your-api-token>
```

---

### 5. Activate and configure

1. In the Dynatrace UI go to **Hub → Manage → Extension Execution Controller → custom:sql.mssql.wait-stats**
2. Click **Activate** on the version you just uploaded
3. Add a monitoring configuration:
   - SQL Server host and port
   - Authentication credentials (SQL login or Windows auth)
   - Select the ActiveGate that can reach the SQL Server
4. Optionally set the **Longest Queries Timeout** variable (seconds) to cap slow monitoring queries

## Querying the data

All log-based feature sets can be queried in Dynatrace via **Notebooks** or **Dashboards** using DQL:

```dql
// Active session waits — last 5 minutes
fetch logs, from:now()-5m
| filter event.group == "dmv_active_wait_stats"
| fields instance, server, session_id, wait_type, wait_category,
         wait_time_ms, blocking_session_id, content
| sort toLong(wait_time_ms) desc
| limit 100
```

```dql
// Instance-level wait totals — last 30 minutes
fetch logs, from:now()-30m
| filter event.group == "dmv_instance_wait_stats"
| fields instance, server, wait_type, wait_category,
         waiting_tasks_count, total_wait_time_ms, avg_wait_time_ms
| sort toLong(total_wait_time_ms) desc
| limit 100
```

```dql
// Query Store wait stats — last 2 hours
fetch logs, from:now()-2h
| filter event.group == "query_wait_stats"
| fields instance, server, query_id, wait_category,
         total_wait_time_ms, avg_wait_time_ms, content
| sort toLong(total_wait_time_ms) desc
| limit 100
```

Metric time series (for charting and alerting) are available under:

```
custom:sql.mssql.wait_stats.blocking_session_count
custom:sql.mssql.wait_stats.max_active_wait_ms
custom:sql.mssql.wait_stats.max_elapsed_ms
custom:sql.mssql.wait_stats.lock_wait_total_ms
custom:sql.mssql.wait_stats.io_wait_total_ms
custom:sql.mssql.wait_stats.cpu_wait_total_ms
```
